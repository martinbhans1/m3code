# Threads on a message

When one answer covers three things, replying to it means answering all three at
once — and the reply that comes back covers all three again. Points get missed,
and the conversation turns into a knot.

A **thread** unties it. Pick the one part you want to go into, open a thread on
it, and have that conversation on its own. The main conversation stays where it
was.

## Opening one

Two ways, both on any message — yours or the agent's:

- **Hover the message** and click the threads icon, next to copy.
- **Select the exact text** you want to talk about and click **Reply in thread**
  on the pill that appears. The selection is quoted into the reply box, so the
  agent knows which sentence you mean without you describing it.

The thread opens as a tab in the right panel: the message at the top, the
replies below it, and a box to write in. Several threads can be open at once,
each in its own tab — three tangents from one answer become three tabs.

Back in the conversation, the message the thread hangs off grows a **"2 replies"**
pill. Click it to reopen the thread.

## What the agent sees

The same conversation it always had. A thread is not a separate session and does
not fork anything: the reply goes to the same agent, with the same model, mode,
branch and worktree, and everything it already knows stays in context. What the
thread changes is where the exchange is _filed_ — the reply and the answer live
under the message they are about, instead of piling onto the end.

That is also why a thread reply cannot run at the same time as the main
conversation. One agent, one turn at a time: a reply typed while it is busy joins
the queue and says so.

## What does not go in a thread

Attachments, slash commands and the model picker stay in the main composer. A
thread is for pinning down one point, not for starting a piece of work — and
since the reply inherits the conversation's settings anyway, there is nothing to
choose. If a tangent turns into real work, ask the agent to run it in the main
conversation, or spin it off as its own.

Threads do not nest. A message inside a thread has no thread of its own.
